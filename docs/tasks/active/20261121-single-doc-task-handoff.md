# Task: Single-Document Zero-Context Task Handoff and User-Oriented Core Need / Design Philosophy

## Goal & Why

Keel dispatches writers and independent verifiers into fresh processes with zero parent chat history (`R2`, `P2`, `D1`). Previously, `keel agent run` required a separate `--why` CLI flag described as `"1-3 sentences"` even when `--task-file` already pointed to a structured `docs/tasks/{active,todo}/<YYYYMMDD>-<slug>.md` specification containing `## Goal & Why`. Splitting the handoff across a short CLI flag and a file had three bad side effects in practice:
1. Orchestrators duplicated `Why` across `--why` and `## Goal & Why` (or wrote terse 1–2 sentence briefs instead of thorough, zero-context-ready specifications).
2. `keel branch verify` ignored the task specification's `## Goal & Why` when building `## Why (Global Alignment)`, falling back to generic boilerplate unless `--why` was repeated on the CLI.
3. Branch-authored `## Progress` and `## Decisions & Findings` (including evidence-backed rebuttals to disputed review findings) were not surfaced alongside `main`'s locked specification when `verify_branch` assembled the verification brief.

This slice makes `docs/tasks/{active,todo}/<YYYYMMDD>-<slug>.md` the single authoritative handoff contract for both writers and verifiers—encouraging thorough, self-contained specifications proportional to slice complexity with zero sentence/line ceilings—while preserving lightweight `--why` + `--task` runs for branches without task files (`D1`).

At the same time, it fixes two foundational repository-documentation gaps across Keel itself and all repositories using Keel:
1. **User-oriented `## Core need`:** `Core need` is the **human user's** core need—who the user is, what they want to accomplish, and where their real pain points lie—never feature checklists, architecture summaries, or developer self-indulgence ("技术自嗨").
2. **Dual-tier `## Design Philosophy` (concise in root `AGENTS.md` + detailed in `docs/requirements.md` / PRD):** Bridging `Core need` (why the project exists for the user) to `Architecture & Boundaries` (concrete modules and invariants) requires an explicit `Design Philosophy` layer stating what core tradeoffs the project believes in and what temptations it rejects—concise (3–5 crisp beliefs, zero generic platitudes) as Section 2 of root `AGENTS.md`, and detailed in `docs/requirements.md` (or `docs/prd.md`).

## Done-check

1. `keel agent run --level L2 --worktree <slug> --task-file <spec.md>` succeeds without `--why` when `<spec.md>` has a non-empty `## Goal & Why` or `## Why` section (ignoring headings inside fenced code blocks), and fails cleanly with exit code 2 and zero orphan run directory when both `--why` and `## Goal & Why` / `## Why` are absent/empty.
